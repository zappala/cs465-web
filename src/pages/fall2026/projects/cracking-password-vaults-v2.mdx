## Objectives

You have managed to breach the storage of a password manager company and
obtained encrypted vaults for each of their users. You have some particular
vaults that you are interested in decrypting because they contain the username
and password for some accounts for "interesting" individuals. You believe these
individuals may have a weak password that may appear in a separate list of
breached passwords you have acquired.

## Project Setup

Download [the handout](/code/cracking-password-vaults/v2/cracking-password-vaults.zip)
for this assignment and unzip it. It contains:

- a folder called `practice`, which contains a practice vault and the password
  for this vault
- a folder called `breach`, which contains:
  - a set of vaults that you have obtained from a password manager company
  - a set of passwords that you have separately obtained from a password breach
    dataset
- a `Cargo.toml` that lists the crates you need, and a `src/main.rs` where you
  write your code

You need Rust 1.98 or newer, the same version the Rust book uses. Run
`rustup update` to get the latest version.

Run your code with `cargo run --release`. Each password guess runs 600,000
rounds of PBKDF2, so cracking all the vaults takes a few seconds in a release
build and several minutes in a debug build.

## Password Vaults

The password vaults have been encrypted with the following process, which is
how password managers protect vaults today:

<Image
  alt="PBKDF2 turns the password and salt into a password key. AES GCM encrypts a random vault key with the password key, giving the wrapped vault key. AES GCM encrypts the vault with the vault key, giving the encrypted vault."
  src={vault_encryption_process}
/>

- The password and a random 16-byte salt go through 600,000 rounds of PBKDF2,
  a password-based key derivation function, to make a 32-byte **password
  key**.
- The vault itself is encrypted with a random 32-byte **vault key**, using AES
  GCM and a random **vault nonce**.
- The vault key is then encrypted with the password key, using AES GCM and a
  random **key nonce**. This is called _wrapping_ the vault key.

Wrapping means the user can change their password without re-encrypting the
whole vault: only the vault key needs to be wrapped again with the new password
key.

The salt, nonces, wrapped key, and vault are coded into hex values. The
password manager company stores each user's vault and its associated
information on one line, in this format:

`username:hex_salt:hex_key_nonce:hex_wrapped_key:hex_vault_nonce:hex_vault`

## Practice Vault

As a first step, write code to decrypt the practice vault. You have the password
for this vault, so you can work through the steps to decrypt a vault:

- convert each field from hex to bytes using the
  [base16ct](https://docs.rs/base16ct/latest/base16ct/) crate:

  - the salt is 16 bytes of `u8`
  - the key nonce and the vault nonce are 12 bytes of `u8` each
  - the wrapped key is 48 bytes: the 32-byte vault key plus AES GCM's 16-byte
    authentication tag
  - the vault is variable size, so convert it to a vector of `u8`

- use the password and the salt with
  [pbkdf2](https://docs.rs/pbkdf2/latest/pbkdf2/) (PBKDF2-HMAC-SHA256, 600,000
  rounds) to make the password key

- use the password key and the key nonce with
  [AES GCM](https://docs.rs/aes-gcm/latest/aes_gcm/) to decrypt the wrapped
  key; this gives you the vault key

- use the vault key and the vault nonce with AES GCM to decrypt the vault

- print the username and the vault contents

## Breach Vaults

For each of the vaults, try each of the breach passwords to see if one of them
works to decrypt the vault.

- If a password is wrong, it makes the wrong password key, and decrypting the
  wrapped key fails: AES GCM checks its authentication tag and returns an
  error instead of a vault key.
- If a password is right, the wrapped key decrypts, and you can use the vault
  key to decrypt the vault. You don't need to try any more passwords for that
  vault.

It is possible none of the passwords match for any given vault. You should be
able to crack 3 of the 6 vaults.

## How Real Password Managers Compare

Notice that the attacker doesn't need any stored password hash. The encrypted
data alone shows whether a guess is right, so the only things slowing the
attacker down are how strong the user's password is and how expensive each
guess is.

- **LastPass** used 100,100 rounds of PBKDF2 when attackers stole its users'
  encrypted vaults in 2022, and some older accounts were still set to 5,000
  rounds or fewer. It also left each vault's website URLs unencrypted, which
  attackers could use to decide which vaults were worth cracking first. It now
  uses 600,000 rounds and has said it will encrypt URLs.
  ([Wladimir Palant](https://palant.de/2023/02/28/lastpass-breach-update-the-few-additional-bits-of-information/)
  describes what was stolen.)
- **Bitwarden** requires at least 600,000 rounds of PBKDF2, the current
  [OWASP recommendation](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
  for PBKDF2-HMAC-SHA256, or lets users choose Argon2id, a key derivation
  function that also uses a lot of memory so that guessing on GPUs is more
  expensive. ([Bitwarden's KDF page](https://bitwarden.com/help/kdf-algorithms/))
- **1Password** combines the password with a random 128-bit Secret Key that is
  stored only on the user's devices, never on 1Password's servers. Someone who
  steals the encrypted vaults from the server can't crack them by guessing
  passwords, even weak ones, because they don't have the Secret Key.
  ([1Password's Secret Key](https://support.1password.com/secret-key-security/))

Password managers also need to let you log in to their servers, so they store
something that checks your password. Good designs derive this from the
password key and then hash it again on the server, so it is no easier to crack
than the vault itself.
